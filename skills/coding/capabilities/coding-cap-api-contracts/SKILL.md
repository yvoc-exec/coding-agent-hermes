# API and Protocol Contract Engineering

Map request construction through routing, authn/authz, validation, domain behavior, persistence and response translation. Check clients, generated schemas, pagination, errors, idempotency, HTTP/gRPC/WebSocket contract semantics and versioning. Use real examples/tests to distinguish transport acceptance from persisted effect. Preserve wire compatibility by default. For security-sensitive API behavior, verify cross-user/tenant assumptions without touching real accounts or production systems. Add contract-level negative tests where possible.

Read the owning Domain or Methodology when the concrete task triggers it. Preserve operator scope and explicit test evidence.
