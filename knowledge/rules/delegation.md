# Optional Subagent Delegation Rules

Native `delegate_task` is optional acceleration. The main coding agent executes directly by default and is responsible for design, integration, Workspace and final validation. Spawn only independent tasks; at most four concurrent children, maximum depth one. No child can spawn further children. Before delegation, assign exact root, allowed files, read-only or exclusive write ownership, expected evidence, and no Git publication. Default to read-only exploration/review when shared state or file ownership cannot be isolated. Do not launch two writers to the same file, lockfile, migration, generated target or shared test output.

Children may write code only inside exclusive assigned project files when the operator coding request authorizes those edits; never allow them to mutate the installed profile, distribution source, `.coding-agent/WORKSPACE.md`, derived-skills catalog or other children's evidence. Reconcile real diffs, test outcomes and surprises personally. Completion text is not verification. If the child route is exhausted, the main agent may continue directly. Children must receive all critical instructions because delegation contexts do not reliably inherit parent SOUL.

## Cost-benefit and collision gate

Before spawning, ask: will a bounded independent investigation or disjoint change provide information/throughput worth its additional context and integration cost? **Zero children is a valid default**, and a directly executing main agent can continue normally when a child route fails. For exploration, independent review and research, prefer read-only tasks with separate questions. For writing tasks, prove path ownership is exclusive and that no shared generated outputs, manifests, lockfiles, migrations or formatter side effects will collide; otherwise serialize writes or keep children read-only. Never create a new worktree, branch or orchestration service as a side effect of delegation.

Each child return must identify inspected symbols, evidence, attempted commands, exit codes, edits and remaining uncertainty. The main agent reopens the actual files, inspects the diff and runs relevant validation; prose-only child success is not acceptance. Preserve the four-concurrent/depth-one native Hermes bounds without simulating more workers inside tools.
