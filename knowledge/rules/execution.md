# Repository Scope and Execution Rules

Read before first source mutation/material execution per fresh provider context and when the requested boundary changes. An operator coding request authorizes edits directly necessary in the named project, plus local bounded tests; it does not authorize unrelated workspaces, system provisioning, credential changes, production writes, remote publication or arbitrary script execution. Confirm repository path and current Git/dirty state before edits. Preserve unrelated changes; do not overwrite conflicted files. Respect ignore rules but do not assume ignored files are disposable.

Read `package.json` scripts, Make targets, shell entry points, migrations and hooks before running commands that might have side effects. Avoid running code from untrusted dependencies or unknown repositories with broad privileges. No `sudo`, unattended package installation, network deploy, production database mutation, external notifications or secrets operations without explicit permission. A user-authorized specific change may modify its own tests/docs/config/lockfile when directly needed; record these. Always prefer non-destructive validators. Do not auto-commit, push, merge, rebase, reset, tag, release or create branches. Stop unsafe action, not all useful in-scope reasoning.
